## [0.4.2] - 2026-09-08

### Added
- Multi-platform native CLI distribution via npm/npx under `@zhconv/cli` and `@zhconv/cli-opencc` with automatic platform resolution across Linux, macOS, and Windows (x64/arm64).
- Dynamic CLI usage snippet generator in the web interface control panel.
- Standalone `bench-compare` crate isolating comparison benchmarks that require legacy OpenCC C library bindings from the main workspace.

### Changed
- Synchronized OpenCC conversion tables with upstream commit `26753884f1`.
- Upgraded `worker` and `worker-macros` to `0.8` for Cloudflare Workers compatibility.
- Cleaned up core code quality: replaced unwrap calls with `?` in CLI, improved docstrings across PyO3 bindings, and clarified MIT compatibility guidance.
- Cleaned up legacy Create React App files in `web/` and updated TypeScript compilation target to ES2020.

### Fixed
- OpenCC dictionary parsing: ignore `#`-prefixed comment lines and strip leading UTF-8 BOM (`\u{feff}`) in `build.rs`, preventing metadata comments from entering dictionaries as conversion rules (e.g. converting `Formatter#start` to `Formatterustart`) ([#12](https://github.com/Gowee/zhconv-rs/issues/12)).
- Added build-time assertion ensuring no surrogate control characters in `[0x00, 0x20)` pollute compressed conversion tables.
- Fixed `wasm-opt` validation failures on Rust 1.87+ by enabling `--enable-bulk-memory` and `--enable-mutable-globals`.
- Fixed Cloudflare Workers `externref` catch-wrapper transform by setting `strip = false` and passing `-C target-feature=+reference-types`.
- Fixed workspace feature propagation between `zhconv`, `zhconv-pyo3`, and `zhconv-worker` so regional conversion tables are properly bundled.
- Fixed `clippy::iter_kv_map` warning by using `.values()`.
- Crate packaging: configure explicit `include` allowlist in `Cargo.toml`, reducing `.crate` tarball from ~13 MB down to ~685 KB and preventing crates.io 10MB limit upload failures.
- Fixed GitHub Actions release workflow to package both default and OpenCC binary variants for GitHub Releases.
- Fixed `@zhconv/cli-opencc` launcher script to dynamically resolve `@zhconv/cli-opencc-*` platform packages instead of default packages.

## [0.4.1] - 2026-02-05

### Added
- Web UI: support direct in-browser conversion of uploaded text files.
- Web UI: allow independent selection of MediaWiki and OpenCC rulesets, or using both concurrently.
- Web UI: dynamic variant filtering to hide target variants unsupported by the currently active ruleset.

### Changed
- Introduced fine-grained Cargo feature flags for conversion tables (`{mediawiki,opencc}-{hans,hant,cn,tw,hk}`).
- Omitted `!TWVariants` and `!HKVariants` when targeting `zh-cn` in OpenCC rules to prevent false-positive reverse character conversions (e.g. `么 -> 幺`).
- Omitted no-op pairs during character replacement counting to enhance `infer_variant` accuracy.
- Replaced `once_cell` with standard library `std::sync::LazyLock`.
- Modernized web application stack with React 19, Material UI v7, Vite, and Yarn Berry (v4).
- Synchronized rulesets with upstream MediaWiki and OpenCC.

## [0.4.0] - 2025-12-02

### Added
- Automated release workflow bundling prebuilt OpenCC binaries across supported architectures.
- Comprehensive benchmark comparisons against other Chinese conversion crates (`opencc-rust`, `ferrous-opencc`, `fast2s`).
- Diagnostic logging in `build.rs` detailing loaded ruleset counts and deduplication statistics.

### Changed
- Disabled `wasm` feature by default in the core crate to reduce footprint when consumed as a library ([#5](https://github.com/Gowee/zhconv-rs/pull/5)).
- Made OpenCC Taiwan phrase mappings (`opencc-twp`) optional to avoid overly aggressive regional substitutions.
- Updated upstream rulesets and refreshed CI configurations.

## [0.3.3] - 2025-01-15

### Added
- Cloudflare Worker: configurable request body limit and numeric boolean query parameter support (`0` & `1`).
- Web UI: automatic conversion trigger upon option changes.

### Changed
- Migrated the repository to a Cargo workspace layout containing `pyo3` and `worker` member crates.

### Fixed
- Fixed nested wikitext conversion rule parsing to align with MediaWiki upstream behavior.
- Fixed panic in `convert_to_with` when skipping characters at text boundaries (closes [#7](https://github.com/Gowee/zhconv-rs/issues/7)).
- Fixed Cloudflare Worker authorization validation and router capture syntax.

## [0.3.2] - 2024-11-27

### Added
- Initial Typst plugin integration (`typst/`) with kebab-case function naming.
- Added `wasm` feature flag for explicit WebAssembly builds.

### Changed
- Updated data rulesets from upstream.

### Fixed
- Resolved PyO3 CI release environment and module naming discrepancies.
- Fixed Windows line-ending CRLF checksum mismatches via updated `.gitattributes`.

## [0.3.1] - 2024-03-22

### Changed
- Made OpenCC rulesets optional in WASM builds to reduce output bundle size.
- Disabled OpenCC rules by default in the core library for faster builds and smaller binary size.
- Applied more conservative handling for one-to-many character conversions.
- Documented performance benchmarks and bundle size trade-offs for the v0.3 series.

## [0.3.0] - 2023-07-05

### Added
- Switched conversion engine to Double-Array Aho-Corasick (`daachorse`) for high-performance linear-time matching.
- Implemented run-length surrogate compression (`pair_reduce` / `pair_expand`) to reduce bundled binary table size.
- Added temporary secondary automaton for parsing and applying complex global rules (`-{H|...}-`) in wikitext.
- Introduced more intuitive confidence scoring in `infer_variant_confidence`.
- Added `TruncatedAround` helper trait for string inspection and truncation.
- CLI: added support for dumping built-in conversion tables.

### Changed
- Ensured earlier conversion pairs take precedence when constructing reverse conversion stages.
- Deduplicated regional tables (`zh-tw`, `zh-hk`, `zh-cn`) against base tables (`zh-hant`, `zh-hans`) to avoid redundant memory usage.

### Fixed
- Fixed build failures when the `compress` feature flag was disabled.

## [0.2.0] - 2023-05-15

### Added
- Introduced OpenCC conversion rulesets alongside MediaWiki rulesets.
- Added ruleset precedence for regional variants (TW, HK, CN).
- Web UI: persisted selected variant in `localStorage` in addition to URL hash.
- Web UI: displayed OpenCC commit hash in the about dialog.

## [0.1.0] - 2022-09-08

### Added
- Initial stable release of `zhconv-rs`.
- Core Chinese conversion engine powered by MediaWiki's `ZhConversion.php`.
- Multi-platform support: native Rust library, CLI, WebAssembly (WASM), and Python bindings (PyO3).
- Relicensed to GPL-2.0-or-later for broader compatibility with MediaWiki data sources.
